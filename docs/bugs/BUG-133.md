# BUG-133 — Incidencias & Soporte: «Resueltas» no se actualiza al resolver

- **Zona:** admin/ops (web y app)
- **Prioridad:** alta
- **Estado:** en revisión
- **Asignado:** claude

## Descripción
Al resolver una incidencia, la lista de resueltas, el contador «críticas» del menú lateral y el punto de la campana no se actualizan. En la app, resolver falla siempre y no hay pestaña de Resueltas.

## Solución
- **Web:** el contador de críticas de `OpsPanel` solo se cargaba al abrir el panel, y las listas dependían del estado en memoria. Ahora `resolverIncidencia` emite el evento `mira:incidencias` (`EVENTO_INCIDENCIAS`). `OpsPanel` vuelve a calcular las críticas y `OpsIncidencias`/`Admin.jsx` vuelven a pedir pendientes y resueltas a la API (si falla, se conserva lo que había). También cubre lo que se resuelve desde el dashboard.
- **App:** `resolverIncidencia(id)` se enviaba sin cuerpo y la API (zod) respondía siempre 400. Ahora pide `{ propuestaResolucion, solucion, encargado }` con la misma validación que la web. `OpsIncidencias` tiene un modal de resolución y una pestaña «Pendientes / Resueltas» (`listarResueltas`). El menú lateral se refresca con `alResolverIncidencia`.

- Verificación: `npm test`, `npm run build` y `npx expo lint`. No se ha podido probar en el navegador porque el panel exige iniciar sesión como admin real.

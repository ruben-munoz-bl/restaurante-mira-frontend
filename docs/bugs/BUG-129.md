# BUG-129 — Botones rojos de eliminar demasiado claros en modo oscuro

- **Zona:** tema
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** claude
- **Rama:** fix/claude-tanda4

## Pasos para reproducir
1. Activar el modo oscuro.
2. Localizar botones rojos de eliminar (admin, listas, cuentas…).

## Resultado esperado
Rojo legible y con contraste suficiente sobre fondo oscuro (textos blancos/oscuros legibles encima).

## Resultado actual
El rojo se ve demasiado claro (casi pastel) y pierde lectura como acción destructiva.

## Notas / capturas
Hallazgo del usuario tras la tanda 3. «Un problema similar con el botón de borrar/rojo del panel de admin, solo que es siempre». Botones afectados: `.ops-btn.danger` (eliminar restaurante/usuario, purgar auditoría) en `src/styles/ops.css`.

## Solución

Causa: `.ops-btn.danger` usa `background: var(--ops-error)`; en oscuro `--ops-error` es `#ffb3c1` (rosa claro, pensado para texto/iconos de error sobre fondos oscuros) y con el texto blanco encima pierde todo el contraste, siempre (no solo en hover, que no tiene regla propia). Archivo: `src/styles/ops.css`. Añadida la regla `[data-theme='dark'] .ops-btn.danger { background: #ba1a1a }` (mismo rojo del tema claro, blanco encima legible); el token rosa sigue usándose en textos/kpis/pills donde sí funciona. Verificación: `npm test` 167/167 y `npm run build` OK en `fix/claude-tanda4`. Pendiente de revisión.
